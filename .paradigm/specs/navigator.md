# Navigator Specification

> Paradigm Navigator v1.0 | AI Exploration Optimization

## Overview

The Navigator system provides a pre-indexed project structure to reduce token waste during AI exploration. Instead of broad file system exploration, AI tools can query the navigator for targeted paths.

## Storage

```
.paradigm/
  navigator.yaml      # Auto-generated structure index
```

## Schema: navigator.yaml

```yaml
version: "1.0"
generated: "2026-02-02T10:00:00Z"

structure:
  features:
    paths: ["src/features/", "features/"]
    symbol: "#"
  components:
    paths: ["src/components/", "lib/"]
    symbol: "#"
  gates:
    paths: ["middleware/", "auth/", "guards/"]
    symbol: "^"
  flows:
    paths: ["flows/", "workflows/"]
    symbol: "$"
  integrations:
    paths: ["integrations/", "external/"]
    symbol: "#"

key_files:
  config: [".paradigm/config.yaml", "package.json"]
  entry: ["src/index.ts", "index.ts"]
  types: ["src/types/"]

skip_patterns:
  always: ["node_modules/", "dist/", ".git/"]
  unless_testing: ["**/*.test.ts", "**/*.spec.ts"]
  unless_docs: ["docs/", "*.md"]

symbols:
  "#checkout": "src/features/checkout/"
  "#Button": "src/components/Button.tsx"
  "^authenticated": "middleware/auth.ts"
```

## Generation

The navigator is auto-generated by `paradigm scan`:

```bash
paradigm scan
# Also generates: .paradigm/navigator.yaml
```

### How It's Generated

1. **structure**: Inferred from existing directory patterns
   - Scans for common directory names (features, components, middleware, etc.)
   - Maps to corresponding symbol prefixes

2. **key_files**: Detected from common file patterns
   - Config files: package.json, tsconfig.json, .paradigm/config.yaml
   - Entry points: src/index.ts, main.ts
   - Types: src/types/, types/

3. **skip_patterns**: Combines defaults with .gitignore
   - Default patterns for node_modules, dist, .git
   - Incorporates relevant .gitignore entries

4. **symbols**: Built from .purpose files
   - Each symbol mapped to its containing directory
   - Direct lookup from symbol to path

## MCP Tool: paradigm_navigate

Query the navigator for targeted exploration.

### Input

```typescript
{
  intent: 'find' | 'explore' | 'context',
  target?: string,  // Symbol or area name
  task?: string,    // Free-form task description
}
```

### Intents

| Intent | Purpose | Required Params |
|--------|---------|-----------------|
| `find` | Locate a specific symbol or path | `target` |
| `explore` | Browse an area or category | `target` |
| `context` | Get context for a task | `task` |

### Examples

```typescript
// Find a symbol
paradigm_navigate({ intent: "find", target: "#checkout" })
// → { paths: ["src/features/checkout/"], symbols: ["#checkout"], ... }

// Explore an area
paradigm_navigate({ intent: "explore", target: "authentication" })
// → { paths: ["middleware/auth.ts", "src/auth/"], symbols: ["^authenticated"], ... }

// Get context for a task
paradigm_navigate({ intent: "context", task: "add Apple Pay to checkout" })
// → { paths: ["src/features/checkout/", ".paradigm/config.yaml"], symbols: ["#checkout", "#stripe-client"], ... }
```

### Output

```typescript
{
  paths: string[],           // Files/directories to read
  symbols: string[],         // Related symbols found
  skip: string[],            // Patterns to avoid
  suggested_order: string[], // Recommended reading order
  explanation?: string,      // Why these paths were selected
}
```

## Exploration Protocol

The navigator teaches AI tools an efficient exploration pattern:

### Before Exploring

1. Read `.paradigm/navigator.yaml` for structure map
2. Query by symbol → go directly to path
3. Respect skip patterns

### Instead of Broad Exploration

```
❌ BAD (expensive):
   glob **/*.ts
   → Returns thousands of files
   → Wastes tokens scanning node_modules

✅ GOOD (targeted):
   paradigm_navigate({ intent: "find", target: "#checkout" })
   → Returns: src/features/checkout/
   → Read only what's needed
```

## Task Recipes

### Adding a Feature

1. `paradigm_navigate({ intent: "explore", target: "features" })`
2. Read an existing feature as template
3. Create in the same location

### Modifying a Component

1. `paradigm_navigate({ intent: "find", target: "#Button" })`
2. Go directly to the path
3. Use `paradigm_ripple` to check impact

### Understanding Dependencies

1. `paradigm_navigate({ intent: "context", task: "understand auth flow" })`
2. Read suggested files in order
3. Skip patterns in the `skip` array

## Cost Optimization

| Approach | Token Cost |
|----------|------------|
| Broad glob | ~5000+ tokens |
| Navigator find | ~100-200 tokens |
| Navigator context | ~200-400 tokens |

The navigator significantly reduces exploration overhead by:
1. Pre-indexing structure on scan
2. Direct symbol→path lookup
3. Skip pattern awareness
4. Prioritized reading order

## Relation to Other Systems

| System | Purpose | Relation |
|--------|---------|----------|
| Navigator | Structure index | Provides paths |
| Purpose | Feature context | Populates symbols |
| Wisdom | Team patterns | Consulted after navigation |
| History | Change tracking | Used for fragility check |

## Fallback Behavior

If navigator.yaml doesn't exist:

```typescript
// MCP tool returns fallback
{
  error: "Navigator not found",
  suggestion: "Run 'paradigm scan' to generate navigator.yaml",
  fallback: {
    paths: [".paradigm/config.yaml", "package.json"],
    skip: ["node_modules/", "dist/", ".git/"]
  }
}
```
